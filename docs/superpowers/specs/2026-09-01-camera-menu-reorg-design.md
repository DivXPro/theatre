# Camera Playground 菜单体系重构设计

日期:2026-09-01
状态:待评审

## 背景

camera playground(`packages/playground/src/shared/camera/`)的菜单是在
"路径 = 相机附属"的旧假设下做的。Path/Camera 解耦后(行进进度归路径对象、
跟随开关归相机,对齐 Blender 的 Follow Path 约束 + Evaluation Time),
菜单归属出现系统性错位:

- 相机操作(对齐到路径起点)收在"路径"菜单里
- 物体属性设置(跟随开关)混进 toolbar 下拉
- 编辑模式内的点级操作(删除选中控制点)放在全局菜单,点了只能弹 alert 教学
- 右键相机弹的是路径菜单,相机自己没有右键菜单
- 顶栏 4 个按钮各自写死像素偏移;"Target 丢失"提示条和"资产库"按钮重叠

## 设计原则

1. **toolbar 只承载全局动作**:添加(模型/相机/路径)和导出视频。
   不承载任何具体物体的属性设置。
2. **物体的属性设置归物体面板**(studio 属性面板),物体的动作归
   面板动作区和右键菜单。
3. **编辑模式内的点级操作归编辑浮条**,不进全局菜单。
4. 多相机、多路径:场景里可以有多台相机、多条路径,
   "添加"即创建新实例。

## toolbar(定稿)

四项,从左到右:

| 项 | 行为 |
|---|---|
| 添加模型 | 打开资产库面板(现状的"资产库"按钮语义改名) |
| 添加相机 | 创建一台新相机(含配套 Target),见"多相机"节 |
| 添加路径 | 创建一条新路径对象(空路径),见"多路径"节。**不**自动切任何相机的驱动 |
| 导出视频 | 下拉列出视频输出 sink(现状保留) |

P1(单例阶段)的语义:目标对象已存在时,"添加相机/添加路径"按钮置灰
(多实例在 P2/P3 才开放)。

镜头视角切换**不在** toolbar,移到右键相机菜单。

## 物体面板动作区(需给 studio 补的机制)

studio 的对象面板(DetailPanel)目前完全由属性配置自动生成,
没有放动作按钮的机制。需要新增:**对象面板动作区**——
按对象(地址/类型)注册一组动作按钮,选中该对象时渲染在属性列表区域
(建议放在属性之后)。

扩展 API 形态(草案):

```ts
studio.extend({
  id: '...',
  objectActions?: (obj: ISheetObject) => Array<{
    label: string
    onClick: () => void
    disabled?: boolean
    title?: string
  }> | null
})
```

DetailPanel 渲染属性后,收集所有扩展对当前选中对象返回的动作,
渲染成按钮区。返回 null/空 = 不渲染。

注册内容:

- **相机面板动作区**:相机对齐到路径起点;恢复 Target(仅 Target 缺失时可用)
- **路径面板动作区**:路径平移到相机(对称原则:它写的是路径的变换)

## 右键菜单(按对象拆开)

| 右键目标 | 菜单项 |
|---|---|
| 相机(视锥/机身) | 查看此镜头(设为活动相机并切镜头视角);删除相机(多相机时) |
| 路径线 | 编辑路径(Tab);删除路径 |
| 已放置模型 | gizmo 模式三选;删除(现状保留) |

菜单实现统一改用 studio 的 `useMenu`/`ContextMenu`
(`@toy-box/studio/uiComponents/simpleContextMenu`),
删掉 PathContextMenu/ObjectContextMenu 两套手写样式;
ObjectContextMenu 的 gizmo 模式三段选择用 ContextMenu 的自定义节点保留。

## 编辑模式浮条

点级操作全部收进编辑浮条(编辑模式选中点时出现的 PathPointEditor 区域):

- **加点**:"添加路径"只创建空路径对象,加点是编辑动作,归编辑浮条。
  空路径加点 = 从当前机位播种一段环绕弧(沿用现状播种逻辑,
  但**不**自动切驱动);非空路径加点 = 在末尾续点。
- **删除选中的控制点**:从全局菜单挪入,alert 教学删除。

全局菜单不再出现任何点级操作。

## 顶部 Target 提示条

降级为**纯警告**(不带恢复按钮),挪到工具条下方,修掉与资产库按钮的重叠。
恢复动作在相机面板动作区。

## 多相机

现状:`ShotCamera` 是单例组件,theatreKey 固定 `Shot / Camera` + `Shot / Target`。

目标:每台相机 = 一对 theatre 对象(`Shot / Camera N` + 配套 Target),
"添加相机"创建新对。

要点:

- **活动相机**概念:画中画小窗和镜头视角显示"活动相机"的取景;
  右键"查看此镜头"= 设为活动 + 切镜头视角;导出视频录活动相机。
- 删除相机:右键菜单;至少保留一台(删最后一台时禁止或提示)。
- 每台相机的属性面板独立(各自的跟随开关、朝向绑定等),互不影响。
- 画中画边框/指示随活动相机。

## 多路径

现状:`POS_PATH_KEY` 固定 `'Pos Path'`;`CameraPath`、`getPathMeta`、
编辑模式等已按 metaKey 参数化,大体就绪。

目标:"添加路径"创建新路径对象(空路径,名字自动编号:
Pos Path、Pos Path 2、…)。

要点:

- **相机跟随选项动态化(最大技术难点)**:相机面板的 moveMode 是
  `t.stringLiteral`,选项 = 手动 + 各路径真名。stringLiteral 的选项属于
  sheet.object 的 config,而 config 要求 deep-equal(热更新/重复调用
  不同 config 会炸)。路径增删时选项变化 → config 变化。
  需要解决:可选方向 (a) 路径名单变化时以受控方式重建相机对象 config
  (评估 theatre 是否允许同 key 重声明);(b) 给 studio 的属性系统
  增加"动态选项 stringLiteral"(选项由函数/dataverse 棱镜提供);
  (c) 自定义 prop 编辑器。实现前需 spike 验证,首选 (b) 或 (a)。
- 路径对象的创建/删除走 theatre 对象生命周期;删除路径时,
  跟随它的相机怎么办:跟随开关的存储值指向已删除路径 →
  面板选项回退显示 + 驱动回退手动(现状已有"路径为空回退手动"的先例)。
- 大纲中多条路径各自可选中、进编辑、挂整体变换 gizmo(已参数化)。

## 分阶段实施建议

- **P1 菜单归位(单例语义跑通)**:toolbar 四项(添加相机/添加路径
  此时创建单例);面板动作区机制 + 三个动作下沉;右键菜单按对象拆开
  (含"查看此镜头");编辑浮条收编删点;提示条降级挪位;
  菜单实现统一为 studio ContextMenu。
- **P2 多相机**:相机实例化 + 活动相机 + 添加/删除相机。
- **P3 多路径**:动态路径创建 + 相机跟随选项动态化(含技术 spike)。

P1 完成后菜单体系即符合设计原则;P2/P3 在此结构上扩实例,
不再动菜单归属。

## 明确不做

- toolbar 不放任何物体的属性设置(跟随开关、Target 开关等只在面板)。
- 播种/添加路径不自动切换任何相机的驱动模式。
- 不为右键菜单发明新的样式体系,统一用 studio 现有 ContextMenu。
