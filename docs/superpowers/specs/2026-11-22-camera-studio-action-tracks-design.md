# Camera Studio 白模动作轨 V2 设计

日期 2026-11-22

## 1. 交付范围

首批交付同时支持多轨编排和多通道对象动作。一条轨道可以先放一个同时控制位置、旋
转、缩放的「驶入」片段，再放另一个动作。三种变换的关键帧都属于同一套动作，移动或
裁剪片段时一起改变时间。另一条轨道可以在同一时段播放骨骼预设。

白模动作的可写范围限定为模型根节点的位置、旋转、缩放，以及角色骨骼预设。材质、贴
图、灯光和可见性均在 V2 动作范围之外。模型属性面板隐藏材质分组，旧工程保存的材质
设置继续正常应用。场景相机和现有运镜路径沿用各自的编辑流程。

同通道混合的设计范围限定为两个骨骼动作的交叉过渡。首批交付执行单写者规则，过渡作
为后续独立增量启用。通用权重、多动作叠层、骨骼遮罩、Additive、变速、循环和外推留
待另行设计。

## 2. 轨道、动作与片段

| 概念          | 职责                                                                                                                               |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 轨道 `Track`  | 在时间轴上排放片段。每个模型可有零到多条轨，任一轨可依次放对象动作或兼容的骨骼动作                                                 |
| 动作 `Action` | 保存一套多通道关键帧，或引用资产库中的骨骼预设                                                                                     |
| 片段 `Clip`   | 引用一套动作，并指定场景起点及动作内的入点、出点                                                                                   |
| 通道          | 对象动作的通道为完整的 `position`、`rotation`、`scale`。骨骼动作在编排层视为同一模型的一组骨骼通道，采样层仍区分每根骨骼的变换分量 |

## 3. 最小数据结构

```ts
type AnimationDocumentV2 = {
  version: 2
  tracks: ActionTrack[]
  actions: ObjectAction[]
}

type ActionTrack = {
  id: string
  name: string
  clips: ActionClip[]
}

type ActionClip = {
  id: string
  action:
    | {kind: 'object'; actionId: string}
    | {kind: 'library'; assetId: string}
  startMs: number
  sourceInMs: number
  sourceOutMs: number
}

type ObjectAction = {
  id: string
  name: string
  durationMs: number
  channels: TransformChannel[]
}

type TransformChannel = {
  kind: 'position' | 'rotation' | 'scale'
  keys: TransformKeyframe[]
}

type TransformKeyframe = {
  id: string
  timeMs: number
  value: {x: number; y: number; z: number}
}
```

- 轨道按保存顺序显示。模型内的轨道、片段、动作及关键帧使用稳定 ID，片段 ID 跨轨
  唯一。轨道顺序只用于显示，互换轨道顺序不会改变求值。
- 位置和缩放沿用模型局部坐标与现有属性单位。旋转使用现有模型属性的欧拉角单位和顺
  序存储，采样时转为四元数。每种通道最多出现一次，启用的通道至少有一个关键帧。各
  通道可独立设帧，也可一次为多项记录同一时间的关键帧。
- 动作时长为正值，关键帧时间为动作内的有限毫秒值，范围为
  `0 ≤ timeMs ≤ durationMs`。同通道同一时刻再次记录时更新原关键帧。动作可被多个
  片段引用。编辑共享动作时显示引用数量，默认复制给当前片段，用户可选择更新全部引
  用。保存动作改动前，重新验证受影响的片段。
- 片段原速播
  放。`endMs = startMs + sourceOutMs - sourceInMs`，`sourceTimeMs = sourceInMs + timeMs - startMs`。
  时间值有限，编辑时校验 `0 ≤ sourceInMs < sourceOutMs ≤ 动作时长`，以及
  `0 ≤ startMs < endMs ≤ 序列时长`。场景活动区间是 `[startMs, endMs)`，首尾相接
  时由右侧片段接管。移动只改起点，裁剪只改时间映射，动作源关键帧保留。

## 4. 多轨并行与编辑

| 同时出现的两个片段               | 首批交付规则                                                                                   |
| -------------------------------- | ---------------------------------------------------------------------------------------------- |
| 同一轨道上的任意两个片段         | 时间区间互斥                                                                                   |
| 不同轨道的对象动作               | 写入不同变换通道时可并行。同一通道的 X、Y、Z 作为一组，例如只改 X 的位置片段仍占用整个位置通道 |
| 不同轨道的对象动作与骨骼预设     | 可并行。对象动作写模型根节点，预设只写骨骼。骨架中的根骨与模型根节点分别处理                   |
| 不同轨道、同一模型的两个骨骼预设 | 首批交付保持互斥。后续只有显式声明过渡的一对片段可重叠，规则见第 5 节                          |

交互沿用现有片段方式：

1. 新放入的模型初始没有动作轨。从模型右键或属性面板选择「添加动作轨到时间轴」，
   创建一条空轨并展开时间轴。已有轨道时同一入口可继续加轨。普通道具也可以创建对
   象动作。
2. 在轨道行头点「＋ 添加片段」。弹窗选择骨骼预设、已有对象动作或新建对象动作，默
   认起点吸附到播放头。骨骼预设仅显示兼容素材，默认填写完整素材时长。新建对象动
   作时勾选位置、旋转、缩放中的一项或多项，默认使用 1 秒与序列剩余时长中的较小
   值。
3. 选中片段后点右侧「编辑动作关键帧」，在动作编辑视图设置局部时间，再用右栏的菱
   形逐组打点。新建时把当前画面中的模型变换写成所选通道的第一个关键帧。已有自建
   动作沿用同一个入口和编辑过程。
4. 点击片段选中和高亮，拖主体移动整段，编辑面板负责裁剪和切换轨道。复用播放头、
   片段边界和网格的吸附反馈。提交前按最新文档校验候选编辑，一次成功编辑对应一步
   撤销。

添加、移动、裁剪及修改共享动作走同一套校验。冲突提示给出片段、轨道、重叠区间和通
道，例如「动作 2 的『侧移』与动作 1 的『入场』在 2–3 秒都控制位置」。零时长素
材、超出素材范围和超出场景范围各有单独提示。失败时保留输入，并保持项目数据与历史
记录。

### 4.2 布局与状态

- **时间轴负责看区间。** 同一模型的动作轨缩进在对象行下。轨高以约 48–52 px 为起
  点，行头固定在时间网格左侧。对象行的 `＋` 打开类型菜单；轨名旁只放「添加片
  段」，点轨名后在右栏重命名或删除轨道。片段显示动作名、完整区间和选中描边。对象
  动作与骨骼动作采用不同底色，类型在右栏用文字标明。片段很短时允许截断名称，聚焦
  或悬停可读完整名称与区间。场景中没有属性轨、动作轨、路径进度或姿势数据的对象不
  进入时间轴；当前选中的对象临时保留一行，让行头 `＋` 继续作为新建轨道的入口。
- **右栏随选择切换，并停靠在时间轴内部。** 对象属性仍在视口右侧的物体属性面板中
  负责建轨；选中轨道或片段后，时间轴自身向右让出检查器宽度，轨道区收缩，检查器独
  立滚动。轨道态负责轨道设置，片段态分为「片段编排」和「动作内容」。片段编排可编
  辑目标轨、起点、素材入点、素材出点，终点根据原速映射即时计算。动作内容显示通道
  或骨骼素材，自建动作可从片段摘要进入动作编辑视图。取消添加弹窗返回触发按钮，成
  功新增后焦点落在新片段。窄布局仍保留时间轴右栏，仅按可用宽度收缩轨道区；物体属
  性面板限制在时间轴上方，不与其重叠。取消选择后右栏关闭，轨道区恢复全宽。
- **反馈靠近操作。** 空轨在对应行提示 `＋`；没有兼容预设时在源选择处解释，并保留
  自建动作入口。加载中及缺失资产的标记挂在原片段，详细原因在右栏。拖动时以位置预
  览、吸附线和文字提示显示候选状态，非法松手复原。表单错误保留输入并通过警报区朗
  读。删除有片段的轨道先显示删除范围，操作结果可撤销。
- **关键路径可用键盘完成。** 建轨、添加、选轨和选片段均有可聚焦的按钮与完整标
  签，弹窗支持 Escape。精确时间和跨轨移动都能用表单完成。保留现有 Studio 的撤销
  重做，并使用主题令牌承接宿主的浅色和深色主题。

布局参考 Blender NLA 的活动轨添加入口，以及选中条带后在编辑器右侧检查器分别编辑
条带位置和素材范围的做法。Theatre 通过物体属性面板显式建轨，时间轴内部右栏只承接
轨道、片段和动作属性。

### 4.3 动作编辑视图与关键帧录制

双击骨骼动作片段或点击时间轴右栏的「编辑动作」后，底部时间轴切换为动作局部帧。左
侧显示局部帧刻度和所选通道的关键帧，右栏显示进入前的场景帧、循环序号、选骨和数值
输入。选中骨骼即可查看素材原有的关键帧。视口调整和数值输入先产生试摆值，点菱形才
写入当前动作会话。「应用并返回」一起提交会话内的修改，并恢复场景播放头与片段属
性。取消时可放弃会话内修改。

关键帧不是只能录制一次。新动作和已有动作共用同一个动作编辑视图；任何引用该动作的
自建片段都能重新进入，继续新增、更新、移动或删除关键帧。编排轨上的片段负责“何时
播放哪套动作”，动作编辑视图负责“这套动作内部有哪些关键帧”。

“录制轨”是界面状态，不是 `AnimationDocumentV2` 中的第三种轨道，也不会在编排时间
轴里新增一行。数据关系仍然是 `Track → Clip → Action → Channel → Keyframes`。进入
动作编辑视图时，底部暂时切换成动作局部时间尺，并列出该动作启用的位置、旋转、缩放
通道；关闭后恢复原编排轨。同一时间只编辑一个片段引用的动作。

| 当前对象     | 入口                                       | 可执行操作                                   |
| ------------ | ------------------------------------------ | -------------------------------------------- |
| 新建对象动作 | 创建片段后自动进入；也可从片段面板再次进入 | 写入首帧、继续打点、保存为动作               |
| 已有对象动作 | 选中任一引用片段，点「编辑动作关键帧」     | 新增关键帧、更新原点、移动或删除关键帧       |
| 编排轨片段   | 在编排时间轴中拖动、裁剪、换轨             | 调整播放区间和素材范围，不直接编辑通道关键帧 |

右栏是唯一的打点入口。每个启用通道的组标题右侧有一个菱形按钮，语义随当前局部时间
变化：

| 状态                   | 属性面板          | 点击结果                                    |
| ---------------------- | ----------------- | ------------------------------------------- |
| 当前时间没有该组关键帧 | `◇ 在 1.50s 打点` | 把这一组 XYZ 作为新关键帧写入当前动作       |
| 当前时间已有该组关键帧 | `◆ 更新 1.50s`    | 覆盖该组在当前时间的关键帧，保留原关键帧 ID |

- 点击菱形写入整组三个分量，例如位置一次写入 X、Y、Z；旋转和缩放各自保持自己的关
  键帧，不会被连带修改。
- 修改右栏数值但尚未点击菱形时，只形成试摆预览。切换局部时间会丢弃未打点的试摆值
  并提示；点击「恢复试摆值」也会回到动作当前采样值。
- 点击通道行上的已有关键帧，会把局部播放头跳到该时间，并在右栏加载该点记录值。修
  改后点 `◆ 更新`，不会产生重复关键帧。
- 已有关键帧可通过精确时间字段移动，也可显式删除；每个启用通道至少保留一个点。V2
  首批只做手动打点，不启用 Blender 式的 Auto Keyframe。
- 保存时把所有通道改动作为一次事务提交，回到原片段和时间轴播放头；取消有改动的会
  话时确认放弃。共享动作默认「仅此片段（复制动作）」，明确选「全部引用」才同步更
  新所有引用。

不在编排轨上直接编辑关键帧。编排轨的拖动和裁剪已经占用水平拖拽语义，而关键帧还必
须绑定到具体 Action、动作局部时间和共享范围；把两类编辑混在同一行会让“移动片段”
和“移动关键帧”产生歧义。已有动作通过所选片段回到动作编辑视图，能力上仍然是完整可
编辑的。

| Blender                       | Theatre 对应                           |
| ----------------------------- | -------------------------------------- |
| NLA Track / Strip             | 编排轨 / 片段                          |
| Action 与各属性 F-Curve       | 对象动作与位置、旋转、缩放通道         |
| Action Editor、NLA Tweak Mode | 动作编辑视图；从已有片段重开同一套动作 |
| 属性字段旁的菱形按钮          | 右栏各变换组旁的 `◇/◆`                 |
| Auto Keyframe 开关            | V2 不启用；后续可作为独立增量加入      |

参考
[Blender Action Editor](https://docs.blender.org/manual/en/4.5/editors/dope_sheet/modes/action.html)、[编辑已有 NLA 条带](https://docs.blender.org/manual/en/4.5/editors/nla/editing/strip.html)和[手动与自动关键帧](https://docs.blender.org/manual/en/4.5/animation/keyframes/editing.html)。

## 5. 后续增量：两个骨骼动作的过渡

### 5.1 过渡的有效范围

在片段编辑面板选择「设置骨骼动作过渡」，指定出场片段和入场片段。两段必须位于同一
模型的不同轨道，并且都能绑定到该角色的同一骨架。出场片段先开始也先结束。

```text
outgoing.start < incoming.start < outgoing.end < incoming.end
transition.start = incoming.start
transition.end   = outgoing.end
```

过渡长度由两个片段的重叠区间派生。区间为半开
`[transition.start, transition.end)`，精确到毫秒并沿用片段时间比较容差。过渡开始
时完全采用出场姿势，结束时由入场片段接管。区间内同模型最多激活这一对骨骼片段，对
象变换片段仍可同时生效。

启用过渡增量时，文档增加可选 `transitions` 列表，记录
`{id, fromClipId, toClipId}`。时间和权重均从片段推导。片段编辑只在提交后的关系仍
有效时保存。创建过渡或取消过渡时，可以在同一事务里调整片段时序，保证最终结果合
法。删除一端的片段时，同步删除该过渡记录。撤销一次恢复整笔操作。

过渡 UI 从选中的骨骼片段右栏进入。弹窗选择另一轨的入场片段，可同时调整入场起点及
素材范围。提交前显示计算出的重叠区间，无法成对或存在第三片段时在弹窗内给出原因。
成功后两条轨在共用时间范围显示过渡纹理，选中任一端可在右栏查看两端与时长。移除过
渡时先预览恢复互斥所需的时间调整，再一次提交。这部分在后续增量中验证，首批 Mock
走基本的多轨并行流程。

### 5.2 采样与合成

每帧把场景时间分别映射到两个片段各自的素材时间，以当前帧的同一基础骨骼姿势为基
底，得到两个完整姿势。对只被其中一个动作写入的骨骼分量，另一侧取同一帧的基础值。
两侧均未写入的分量直接沿用基础值。随后执行一次成对插值：

```text
p = clamp((timeMs - transition.start) / (transition.end - transition.start), 0, 1)
位置与缩放 = lerp(出场值, 入场值, p)
旋转       = slerp(出场四元数, 入场四元数, p)，走最短弧并归一化
```

复用现有骨骼采样器和 `composePose` 的 Replace 插值能力。实现时先把出场样本全量覆
盖到基础姿势，再把补齐到相同通道集合的入场样本以 `p` 覆盖，得到上述结果。按自身
源时间独立采样，即使两个片段引用同一素材也要覆盖测试。一端素材未就绪时，预览在重
叠区间显示基础姿势和该片段的资源状态，资源就绪后按当前时间重算。采样结束后继续应
用现有姿势和左右手势关键帧，并在导出读取之前完成覆盖。

## 6. 统一求值与场景接入

以 Camera Studio 内部的 `evaluateAt(timeMs, inputs)` 作为统一入口。输入包括该帧
的 Theatre 底层变换、基础姿势、动作文档及已解析的资源。求值返回最终模型根节点变
换、骨骼姿势和诊断，随后由同一帧应用器写入场景。

- **对象变换**沿用 Theatre 已求值的默认值、静态设置和旧关键帧作为底层，只覆盖活
  动片段声明的完整通道。位置和缩放用线性插值，旋转用四元数最短弧插值。片段内早于
  通道首帧或晚于末帧时取最近端点。片段外恢复底层值。
- **骨架**每帧从绑定姿势或静态姿势开始，采样当前骨骼片段，再应用现有姿势和手势覆
  盖。有对象动作轨时，仅在确实编排了骨骼片段的情况下接管旧 `animation` 骨骼播放
  路径。对象动作轨可以与旧动作行为并存。
- **应用顺序**先验证 Camera Studio 放置模型的绑定能将根变换的最终写入交给帧应用
  器。读取 Theatre 基础值时始终从 `SheetObject` 取值，避免回读上一帧的 Three.js
  变换。应用后的模型世界矩阵要在同帧的相机跟随、取景及渲染之前可读。用一个跟随机
  位验证此接入。通用 `SheetObject` 序列层仅在局部接入无法满足实际消费者时再评
  估。
- **播放和暂停**都传入当前序列的绝对时间。正常播放由序列推进，拖播放头和资源就绪
  触发重绘。V2 动作只按绝对时间采样，同一时间的结果与上一帧、播放方向和帧率无
  关。
- **静帧和视频导出**复用现有 `seekFrame` 流程，先定位序列并完成 Theatre 更新，手
  动推进场景帧并应用最终结果，再渲染给编码器。导出会话冻结 V2 动作文档和所需动
  作、姿势及手势资源。同一场景配置是三路一致性验收的前提。导出完成、取消或失败后
  恢复编辑器播放头及预览状态。

现有接入点见
[角色求值](../../../packages/camera-studio/src/PlacementManager.tsx#L1721)、[骨骼采样器](../../../packages/camera-studio/src/animationStrips/sampler.ts#L17)和[导出定位](../../../packages/camera-studio/src/videoExport/previsExporter.ts#L122)。

## 7. 存储与兼容

- 继续存入模型的隐藏属性 `animationTracks`，沿用 Studio 事务保存。读取 V1 时映射
  为 `kind: 'library'` 的 V2 片段，保留轨道 ID、片段 ID、素材引用和时间。合法的
  历史多轨数据保留原轨道。首次成功编辑时写入 V2。迁移阶段不会自动生成过渡。
- 旧属性关键帧数据保留为兼容底层。带旧 `animation` 的角色创建空轨或仅创建对象动
  作时，沿用原骨骼播放。首次加入骨骼片段后由该角色的骨骼编排接管，片段空档使用基
  础姿势；移除最后一个骨骼片段后恢复旧动作路径。
- 无法解析的文档及未知版本原样保留并显示错误。缺失或不兼容素材保留片段位置，预览
  回到对应基础姿势并提示。导出区间依赖该素材时，明确报告模型及素材并停止导出。

## 8. 三路一致性验收

### 8.1 使用同一个 Playground 场景

创建一个 30 fps、6 秒的固定测试场景。从 `0s` 导出，使用导出帧计划的
`timesMs[frameIndex]` 作为场景采样时间，帧索引从 0 开始。

| 轨道       | 片段                                                                                                                      |
| ---------- | ------------------------------------------------------------------------------------------------------------------------- |
| 对象动作轨 | `1–4s`「入场」，在同一片段内录入位置、旋转和缩放。三项在区间内都需要有可测变化                                            |
| 骨骼轨 1   | `0.5–3s`「走路」                                                                                                          |
| 骨骼轨 2   | 首批验证使用 `3–5s`「跑步」，与走路首尾相接。验证过渡增量时把跑步起点移到 `2s`，与走路在 `2–3s` 交叉过渡，保持结束点 `5s` |

使用已加载的本地测试素材和固定机位。跑步素材至少有 3 秒可用时长，过渡场景调整入
场片段起点和素材范围，得到 `2–5s` 的片段。另跑一次跟随机位，确认模型世界矩阵在取
景前更新。首批验收至少检查帧 `0、15、30、75、89、90、120、150`，覆盖片段前、起
点、并行中、相接前一帧、相接边界、对象动作结束及最终空档。过渡增量追加帧
`59、60、75、89、90`，检查开始前、开始、50% 权重、结束前和结束。测试夹具另提供一
条仅出场动作写入的骨骼分量，验证它按权重回到基础值。

### 8.2 逐帧对照

| 入口           | 采集方法                                                                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 暂停后拖播放头 | 走实际播放头入口，到达目标帧后等场景完成更新。正向、倒向及跨空档跳回目标帧各执行一次                                                     |
| 正常播放       | 从零启动正常播放。自动化用受控时钟推进序列和场景帧，在目标时间采集实际应用结果                                                           |
| 导出           | 调用真实的逐帧导出入口。在 `seekFrame` 更新后、渲染和编码前，按帧索引采集实际应用结果。静帧导出用同一个 `timesMs` 抽查并行段、中点及边界 |

比较**已经写进场景**的模型根节点位置、旋转、缩放和骨骼局部变换。位置和缩放逐分量
绝对误差上限为 `1e-5`，旋转以单位四元数夹角比较，`q` 与 `−q` 视为同一姿态，误差
上限为 `1e-4 rad`。同时核对活动片段 ID、素材采样时间和权重。测试夹具对并行中点、
接片边界、空档和过渡中点另有独立预期值，用来捕捉三路共同出现的求值错误。

### 8.3 桌面 Chrome 视频验收

在当前项目的 Playground，用同一场景完整导出 H.264 MP4，再强制走 MediaRecorder 降
级路径完整导出一次。记录实际编码路径、MIME 类型、场景帧索引与输出采样时间。两条
路径都要完成写盘并从文件播放到结尾。对照静帧和解码画面，检查对象变换、走跑接片及
空档。MediaRecorder 的输出抽查按实际媒体时间对应，数值一致性以逐帧编码前的场景采
样记录判定。文件能播放和编码前姿势一致分别记录结果。

## 9. 实施顺序与交付门槛

1. 建立 V2 数据、V1 兼容和轨道/通道校验。把 Studio 附加行注册改为每个模型可返回
   多行，复用现有添加弹窗、选中、裁剪和拖动逻辑。
2. 加入固定三通道动作编辑视图及模型根节点求值；新建动作与已有动作共用同一入口，
   已有片段必须能重新进入并编辑。和骨骼动作一起接入逐帧应用及导出快照。以第 8 节
   的同一场景作为首批交付门槛，同时验证单组打点、已有关键帧更新、共享动作复制，
   以及片段拖动、裁剪、保存重开和撤销重做。
3. 首批交付通过后，按第 5 节接入显式的双骨骼过渡，增加非法第三片段、缺失通道、同
   素材独立采样及过渡边界回归测试，并重跑三路一致性和桌面导出验收。
