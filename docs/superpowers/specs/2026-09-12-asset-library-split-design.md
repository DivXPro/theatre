# 资产库分拆设计:四个独立框体,按使用需要弹出

日期:2026-09-12
状态:已与用户确认设计方向,待实施

## 背景

camera playground 的资产库目前是一个总面板(`AssetLibraryPanel`),内含
模型/姿势/动作/路径 4 个 tab,顶栏一枚「资产库」按钮统一开关。用户要求:
**把资产库拆开,框体按使用需要才显示**——路径、模型这类「新增物体」的框体
在点击新增时弹出;姿势、动作这类绑定具体物体的框体,在选中物体并点击
「改变姿势」等入口时才出现。

## 用户已确认的决策

1. **模型/路径框体 = 顶栏新增按钮弹出**:点「添加模型」弹模型框体,点
   「添加路径」弹路径框体。
2. **姿势/动作框体 = 右键菜单入口**:右键场景里已放置的模型,菜单里点
   「改变姿势」「播放动作」弹对应框体(用户选了右键菜单方案,不选顶栏
   跟随按钮、也不选选中即自动弹)。
3. **框体不自动收起**:放置/套用完后框体保持打开,由用户手动关(点框体
   关闭按钮,或再点对应的顶栏按钮)。
4. **「资产库」总按钮收掉**:顶栏换成「添加模型」「添加路径」两枚独立按钮。

## 设计

### 1. 框体结构

`AssetLibraryPanel` 改为按类型渲染单一内容的框体组件:新增 `kind` 属性
(`'model' | 'pose' | 'animation' | 'path'`),删掉内部 tab 状态和 tab 切换条。
一个组件四个实例,不复制四份代码。

每种框体的头部:类型标题(模型库/姿势库/动作库/路径预设)+ 导入按钮
(路径框体没有)+ 关闭按钮。框体内容按 `kind` 渲染:

- `model`:模型卡片网格(缩略图 + 骨架标签),点击放默认位、拖拽到场景
- `pose`:存当前姿势按钮行 + 姿势卡片网格(点击套用到选中模型)
- `animation`:动作卡片网格(点击套用到选中模型)
- `path`:4 种路径预设卡片(点击放默认位、拖拽到落点)

现有行为全部保留:卡片手势(4px 阈值区分点击/拖拽)、卡片右键菜单
(重命名/删除)、骨架族过滤与置灰、缩略图懒加载、导入确认弹层。

**多个框体可同时开**,位置按类型固定错开(都贴左边缘,横向各错开一小段,
避免完全重叠),各自独立关闭。框体不做拖动移位(YAGNI)。

### 2. 弹出时机与开关状态

App 里一个 `libraryOpen` 换成四个独立开关(model/pose/animation/path),
每种框体有自己的打开/关闭回调:

- **模型框体**:顶栏「添加模型」切换;框体 × 关闭
- **路径框体**:顶栏「添加路径」切换;框体 × 关闭
- **姿势框体**:右键已放置模型 →「改变姿势」打开;框体 × 关闭
- **动作框体**:右键已放置模型 →「播放动作」打开;框体 × 关闭

放置中/拖拽中禁用顶栏「添加模型」「添加路径」的语义保留(沿用现
`libraryDisabled`)。

### 3. 右键菜单加项

`buildObjectMenuItems` 增加两个可选回调 `onChangePose`/`onPlayAnimation`。
提供时菜单结构变为:

```
改变姿势
播放动作
────────
✓移动 / 旋转 / 缩放
────────
删除
```

(用户确认的文案:改变姿势、播放动作;位于现有项上方。)

**出现条件**:右键的放置体是库来源模型(注册表 entry 带 `libraryEntryId`)
才传这两个回调;本地遗留放置体(无库 id)不出现这两项。骨架不匹配/无选中
的置灰由框体现有逻辑兜底,菜单不再额外判骨架类型。

右键本身已会选中该模型(现状),所以框体打开后卡片套用的就是右键的那个
模型。框体打开后如果用户改选别的模型,套用跟随当前选中(与现状一致);
选中丢失时卡片置灰,框体不关。

### 4. 顶栏

`TopToolbar` 的 `onToggleLibrary` 换成 `onToggleModelLibrary` 和
`onTogglePathLibrary`,按钮文案「添加模型」「添加路径」;`libraryDisabled`
对两枚按钮同样生效。顶栏变为:添加模型 / 添加路径 / 添加相机 / 导出视频。

### 5. 组件改动清单(预估)

- `assetLibrary/AssetLibraryPanel.tsx`:加 `kind` 属性、去 tab 条、头部按
  类型渲染;位置按类型错开
- `App.tsx`:四个框体开关状态;四处框体挂载;右键菜单回调打开姿势/动作
  框体;顶栏新回调
- `TopToolbar.tsx`:`onToggleLibrary` → `onToggleModelLibrary` /
  `onTogglePathLibrary`,按钮文案调整
- `menuModel.ts`:`buildObjectMenuItems` 加两个可选回调与两个菜单项
- `menuModel.test.ts`:对象菜单新结构的单测
- `PlacementManager.tsx`:无需改动(右键菜单数据在 App 组装,
  `onObjectMenu` 回调链不变)

### 6. 错误处理

- 框体打开期间目标模型被删除:套用回调里 `selectedPlacement` 失效,卡片
  置灰(现有 `applyDisabled` 链路),不报错
- 姿势/动作框体已开,用户又右键另一个模型点同一项:框体已开则不重复开,
  套用目标自然跟随新选中
- 导入流程不变:文件类型自动识别,与框体类型不强制绑定(在模型框体里
  导入姿势文件,条目仍进姿势库)

### 7. 测试策略

- **jest 纯函数**:`menuModel.test.ts` 断言对象菜单在提供/不提供两个回调
  时的结构(项数、顺序、文案、回调触发)
- **Playwright 手动验收**:
  - 顶栏「添加模型」开模型框体,点击卡片落默认位,拖拽卡片到场景落点
  - 顶栏「添加路径」开路径框体,点击/拖拽预设各一次
  - 右键已放置模型 →「改变姿势」弹姿势框体,点卡片套用到该模型
  - 右键已放置模型 →「播放动作」弹动作框体,点卡片套用
  - 右键非库来源对象(如相机、背景)→ 菜单无这两项
  - 多框体同开互不干扰;框体 × 各自关闭;放置后框体不收起

### 8. 非目标(YAGNI)

- 框体拖动移位、记住开合状态
- 姿势/动作框体的自动弹出(选中即弹,用户已排除)
- 框体用完自动收起(用户已排除)
- 导入按钮按框体类型限制文件类型(维持自动识别)
