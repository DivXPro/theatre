# Camera Studio 动作片段时间轴设计

日期 2026-11-21

范围 Theatre Camera Studio 第一阶段

## 1. 目标与范围

把资产库里的骨骼动作安排在角色时间轴上。用户可以添加、移动、裁剪和删除片段，在暂停时拖动播放头检查姿势，并按同一编排导出视频。每个角色开放一条动作轨，多个角色各自编排。同轨片段可以相接或留空，区间内以原速播放一次。

长期目标是接近 Blender NLA 的编辑和求值行为。沿用源动作、片段和有序轨道的结构，逐步支持变速、重复、外推与多轨混合。第一阶段交付 Theatre 工程中的动作编排。Blender 行为参考见 [NLA Sidebar](https://projects.blender.org/blender/blender-manual/src/branch/main/manual/editors/nla/sidebar.rst?display=rendered)。

## 2. 片段数据与保存

```ts
type CharacterAnimationV1 = {
  version: 1
  tracks: AnimationTrackV1[]
}

type AnimationTrackV1 = {
  id: string
  strips: AnimationStripV1[]
}

type AnimationStripV1 = {
  id: string
  assetId: string
  startMs: number
  sourceInMs: number
  sourceOutMs: number
}
```

- 角色归属由场景 `SheetObject` 决定。轨道和片段使用稳定 ID，移动、裁剪和保存重开都保留原 ID。同一个 `assetId` 可以用于多个片段。
- `tracks` 按从底层到顶层排列。新增第一个片段时创建该角色的第一条轨道。第一版每个角色最多一条轨道，每条轨内按 `startMs` 排序。
- `startMs` 是时间轴位置，`sourceInMs` 和 `sourceOutMs` 是素材内部时间。数值为有限毫秒，可保留小数，以支持非整数毫秒的帧网格。与 Theatre 序列和 Three.js 交接时统一转换为秒。
- 原速下 `endMs = startMs + (sourceOutMs - sourceInMs)`。`endMs` 和时长由同一个函数计算，供编辑、渲染、重叠验证和导出查询使用。使用半开区间 `[startMs, endMs)`，所以相接时由右侧片段接管。
- 新增和编辑时校验 `0 ≤ sourceInMs < sourceOutMs ≤ assetDurationMs`、骨架兼容、场景时间范围及同轨区间互斥。吸附与边界判断共用时间比较规则，覆盖小数毫秒造成的舍入误差。缩短序列后保留已有片段，播放和导出以当前序列范围为准。

将文档序列化到角色对象的隐藏静态属性 `animationTracks`。复用路径注册表已有的 JSON 状态和 Studio 事务模式，按角色独立存储。每次新增、移动、裁剪或删除提交一个事务。模型被删除时，现有 `forgetObject` 清理该属性，撤销模型删除时一起恢复。该属性由片段领域的读写接口管理，普通属性编辑和关键帧编辑入口均隐藏。

空属性及空轨道列表沿用已有 `animation` 播放行为。创建首段时写入片段文档，角色进入片段模式。删除最后一段后保留空轨道，角色显示基础姿势。轨道菜单的「移除动作轨」清空片段文档并恢复已有 `animation` 的播放。已有 `animation` 选择仍保存在工程里，无需批量迁移。

保存数据只带素材引用。缺失、损坏或骨架不兼容的素材保留在原位置并显示错误，用户可以删除片段，或在资源可用后重新加载。无法解析的文档或未知版本原样保留，预览显示基础姿势并提示，片段编辑和涉及该角色的导出报错。

现有接入点见 [路径注册表](../../../packages/camera-studio/src/pathRegistry.ts)、[模型删除事务](../../../packages/camera-studio/src/PlacementManager.tsx#L1955)和[资产类型](../../../packages/camera-studio/src/assetLibrary/types.ts#L41)。

## 3. 时间轴连线复用

在当前角色的 DopeSheet 对象行下显示「动作」行，随现有时间轴一起滚动和缩放。只要角色有骨架就显示这条行，不要求先有关键帧或片段；场景里存在骨架角色时时间轴默认展开，避免空动作轨把唯一入口藏进收拢状态。Studio 增加一个通用的附加行接入点，Camera Studio 为当前场景提供行数据和编辑回调。左右两侧共用行布局，挂载和卸载跟随场景。

```text
角色 A
  动作       ┃ 走路 ┃                  ┃ 挥手 ┃
             1s     4s                5s     7s
```

片段画成带圆角背景的卡片，不再只画一条连线和两个孤立端点。卡片左右各留 12px 裁剪抓手，中间整段都是拖动命中区；抓手内画两条竖向纹理，明确表示「可裁剪」。复用时间轴已有的坐标转换、网格吸附、拖动阈值和 Studio 事务，不复制关键帧编辑器的贝塞尔弹窗与 `transformKeyframes` 逻辑。动作行传入由 `stripId` 标识的片段以及片段编辑回调。

空动作行在右侧轨道里显示「＋ 添加动作」；行头也保留同名入口。动作从播放头位置加入；若该位置已被片段占用，就顺延到占用片段末尾，而不是直接报错。裁剪时位置先夹在素材入出点和序列长度内，拖到素材边界会停住；只有与相邻片段重叠时才拒绝提交，并在片段上显示红色错误描边和 `!` 标记。

| 操作 | 第一版行为 |
| --- | --- |
| 添加 | 从角色的资产选择器将完整动作放到吸附后的播放头位置 |
| 拖中间 | 只改 `startMs`，以首端为吸附基准，保持片段长度和素材范围 |
| 拖左端 | `startMs` 与 `sourceInMs` 同量变化，右端位置固定 |
| 拖右端 | 只改 `sourceOutMs`，左端位置固定 |
| 删除 | 移除当前选中的片段，其他片段位置保持原样 |
| 移除动作轨 | 删除该角色的动作轨及其片段，一次撤销可恢复整轨 |

拖动时在动作行显示候选范围。越界、重叠、素材范围不足或裁到零长度时标记无效，并在松手时保留原状态。松手前基于当前项目状态复核候选编辑，原目标已被其他编辑修改或删除时取消本次拖动。有效拖动松手后提交一次，场景重新求值。支持取消拖动和撤销，一次拖动对应一步历史记录。

点击片段后高亮并打开属性面板，关闭面板后保留选中。面板以秒显示时间轴首尾、素材入出点和时长，应用时一次写入所有改动。平移保持素材范围，修改素材范围保持时间轴起点。拖动时优先吸附到有效的播放头、其他片段首尾或序列边界，并在对齐处显示辅助线。超出吸附距离时沿用时间轴网格。

现有接入点见 [DopeSheet 行布局](../../../packages/studio/src/panels/SequenceEditorPanel/DopeSheet/Right/Right.tsx)和[连线拖动](../../../packages/studio/src/panels/SequenceEditorPanel/DopeSheet/Right/BasicKeyframedTrack/KeyframeEditor/BasicKeyframeConnector.tsx#L197)。

## 4. 播放、拖动与导出的共同求值

Camera Studio 负责两层求值。第一层只读轨道数据，按绝对时间输出当前帧的动作贡献。第二层解析素材并把贡献应用到角色骨架。

```ts
type AnimationContribution = {
  trackId: string
  stripId: string
  assetId: string
  sourceTimeMs: number
  weight: number
}
```

第一版每个角色的结果为零或一项，激活时 `weight = 1`，输出列表按轨道顺序排列。对覆盖 `timeMs` 的片段：

```text
sourceTimeMs = sourceInMs + (timeMs - startMs)
```

第一版实现把第二层再拆成采样与合成两步：采样器只返回骨骼姿势，`composePose(base, samples)` 接收有序 sample 列表并输出最终姿势。当前单轨最多产生一个 sample，按 Replace 和全权重合成；接口保留 sample 数组和权重，为后续多轨混合准备，不在预览、seek 或导出调用点重新分叉求值逻辑。

第一版为空档采用无贡献语义。每次求值先取得角色基础姿势，优先使用静态姿势，否则使用绑定姿势。命中片段时将采样的骨骼通道覆盖到基底上。之后依次应用现有姿势轨和手势轨的覆盖规则，手势只写对应手指骨。姿势编辑会话仍由现有 IK 会话接管，结束会话后重新按播放头求值。

素材加载复用现有动画 GLB 加载路径和骨架校验。角色的采样器可复用 Three.js `AnimationMixer`，在独立的采样骨架上把动作定位到指定的素材时间，并用零增量求值。采样结果再写到场景角色，确保手工姿势覆盖、相同时间重复采样及切换到另一段后都能得到正确结果。每次采样只提交该动作实际绑定的骨骼通道，其余通道沿用基底。采样缓存按角色和素材隔离，退出片段或切换素材时清理当前动作的状态。

| 入口 | 如何调用 |
| --- | --- |
| 正常播放 | 每个渲染帧读取 `sequence.position`，运行角色片段求值器 |
| 暂停和拖播放头 | 播放头、片段编辑或资源就绪时请求渲染，使用同一求值器。片段模式拥有骨骼写入权，现有暂停回写逻辑须让出这条路径 |
| 静帧和视频导出 | 复用导出器的逐帧定位。等待 Theatre 更新到目标位置后，手动推进 R3F 帧，调用同一个角色求值器，再渲染 |

片段模式始终按绝对时间采样。已有静态动画仍走原播放路径。导出开始前固定本次使用的片段数据，解析静帧或请求区间会用到的动作素材及片段角色的姿势、手势库引用。导出逐帧使用这份片段数据和已解析资源，动作轨编辑在下次导出时生效。预览遇到未解析动作时以基础姿势显示并标记状态，到货后以当前时间重算。导出遇到必要资产解析失败时报告具体角色和资产，取消导出并恢复编辑器状态。

## 5. 升级到多轨混合

1. **单轨时间控制。** 在已版本化的片段文档上增加 `scale`、`repeat` 和 `extrapolation`。新版本读取第一版时使用 `scale = 1`、`repeat = 1`、`extrapolation = 'nothing'`，保留起点、素材范围和 ID。普通片段的长度按 `素材范围 × scale × repeat` 派生。`scale > 1` 表示慢放，循环在素材裁剪范围内发生。
2. **同一角色多轨。** 启用现有 `tracks` 数组的第二条及以上轨道。跨轨片段可以同时激活，求值器仍输出有序贡献列表。每份贡献按自身的素材时间独立采样，合成器从基底开始，按轨道顺序逐层做加权 Replace，先明确支持淡入淡出和片段影响权重。第一版轨道留在底层，默认全权重 Replace，原工程的姿势与时间保持一致。
3. **局部和加法层。** Replace 混合稳定后，再加入骨骼遮罩、基于明确参考姿势的 Additive、静音和独奏。遮罩和混合规则属于合成器，姿势和手势关键帧继续在片段合成后覆盖。同一素材由两条轨在不同时间引用时，使用独立采样状态。

新版本的加载器读取旧版本并补齐行为默认值。保存时仅在使用需要的新语义时升级文档版本。保留稳定 ID 和素材引用，任何版本的预览和导出都通过同一个时间求值入口。

## 6. 验收

| 场景 | 通过条件 |
| --- | --- |
| 添加和编排 | 同一角色显示 `1–4s 走路` 与 `5–7s 挥手`。另一角色可独立添加动作 |
| 移动和裁剪 | 拖整段长度不变，拖左右端点时另一端固定且动作原速。非法重叠或越界时项目数据和撤销历史不变化 |
| 边界和空档 | `4s` 进入空档并回到基础姿势，`5s` 显示挥手素材首帧。片段无缝相接时边界只激活右侧。小数毫秒的帧网格也遵守该规则 |
| 预览和导出 | 在资产已就绪后，直接 seek 到 `2.5s`、播放至 `2.5s`、导出包含 `2.5s` 的帧，所得骨骼变换在浮点容差内一致。倒向拖动、跨空档后跳回该点及叠加姿势、手势轨也得到一致结果 |
| 持久化和兼容 | 保存重开、撤销重做、删除模型后撤销，恢复相同 ID、片段时间与素材引用。旧工程中未启用片段轨的角色保持原来的播放方式 |
| 资源异常 | 预览将缺失素材标在原片段上，返回基础姿势。导出该区间时明确报错，重新提供素材后可重试 |
| 未来升级 | 第一版文档补齐变速、重复、外推和混合默认值后，在片段内、边界和空档采样都与第一版一致 |
